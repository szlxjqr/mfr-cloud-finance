## 1. 产品目标

把"现在的对话框"（纯问答体验）移植进 mfr-cloud-finance **首页**，作为统一的业务入口：

- 用户**用自然语言**完成采购 / 报销 / 发票等业务动作与查询，无需打开对应页面、无需点按钮。
- 复杂产出（报表、长表）引导去既有报表页查看，对话框只做"问—答"。
- v1 聚焦**框架 + WorkBuddy 委派**占位，等业务数据（明早清发票重入后）跑通再扩。

## 3. 需求池

### P0（v1 必做）
- P0-1 首页常驻对话面板（浮动/抽屉）+ 模型选择器（仅 WorkBuddy 委派可用，本地/云端 disabled 占位）。
- P0-2 `POST /api/ai/chat` SSE 流式路由，全程 `get_current_user` 鉴权。
- P0-3 Provider 抽象：WorkBuddy 委派 Provider 实接（超纲任务转交、流式回收）；本地/云端 Provider 预留适配层（不接）。
- P0-4 业务工具（采购/报销/发票三域）：`createPurchaseRequisition` / `fromPurchase` / `createReimbursement` / `listInvoices` / `linkInvoice` / `generateReport`（发票相关报表）。
- P0-5 Agent 编排循环：LLM 决定调工具 → 后端鉴权执行 → 结果回灌 → 自然语言答复。
- P0-6 安全分级：A 只读/报表直跑；B 创建单据执行后回显可撤销；C 支付/记账用一句对话确认。
- P0-7 答案渲染：纯 Markdown（含表格）。
- P0-8 会话历史落本地库（按用户隔离），不跨设备。

### P1（v1 顺带 / 视情况）
- P1-1 图片类答案（图表 PNG）渲染（富消息 `image`）。
- P1-2 复杂结果深链到报表页。
- P1-3 工具返回结构化数据 → Markdown 表格自动生成。

### P2（v1 不做，后续）
- P2-1 本地/云端模型实接。
- P2-2 语音输入输出。
- P2-3 向量库 RAG。
- P2-4 工作流编排（多步自动化）。
- P2-5 跨设备/多端同步。

## 5. 待确认问题（原讨论点，已拍板）

| # | 原问题 | 结论（2026-07-26 07:17） |
|---|---|---|
| 1 | 模型策略 v1 | 先只做「框架 + WorkBuddy 委派」占位，本地/云端留适配层；等业务数据跑通再扩 |
| 2 | 写类动作安全 | 纯对话确认，无按钮；C 级用一句确认代替 |
| 3 | 答案渲染 | 纯 Markdown 表格 |
| 4 | WorkBuddy 姿势 | 委派式 (A)：自含轻量 agent + 业务工具，超纲委派 WorkBuddy |
| 5 | v1 工具范围 | 采购 / 报销 / 发票 三域先行 |
| 6 | 会话落库 & 跨设备 | 存历史（落本地库），不跨设备、不 multiple 端，仅本机 |

## 6. 验收口径（v1）

- 首页对话框可开/关/续聊（历史落库）。
- 用 WorkBuddy 委派通道，能完成采购/报销/发票三域的"说—做—答"。
- C 级动作必须对话确认后才执行。
- 答案以 Markdown（含表格）呈现；复杂产出给报表深链。
- 全程鉴权，工具执行复用既有事务与权限。
