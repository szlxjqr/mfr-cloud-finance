# 统一发票上传组件 — 产品需求文档 (PRD)

> 文档编号：PRD-20260725-001
> 产品经理：许清楚
> 创建日期：2026-07-25

---

## 1. 产品目标

统一当前系统中两套发票上传/识别入口（报销单「增加发票」与发票箱「批量上传并识别」），抽为一个多文件上传组件，所有发票统一先入发票池（`invoice_inbox`），各组消费方从发票池取数挂接。

---

## 2. 现状问题

| 问题 | 当前表现 | 影响 |
|------|---------|------|
| 两个不同界面 | BillList.vue 手动录入表单 vs InvoiceInbox.vue 上传 → OCR → 暂存 | 用户认知混乱，不知道用哪个 |
| 都不支持多文件 | 单文件上传 | 大批发票要一张一张传 |
| 数据流不一致 | 报销单「增加发票」直接入库成正式 Invoice，不走发票池 | 池中发票看不到，消费方无法统一管理 |
| 挂发票弹窗看不到池中发票 | 只查 `invoices` 表 `reimbursement_bill_id IS NULL` | 发票池里已识别的发票在挂发票时看不到 |

## 3. 用户故事

### P0（本次必须做）

| ID | 角色 | 故事 | 验收标准 |
|----|------|------|---------|
| US-01 | 财务/报销人 | 在报销单编辑页上传多张发票（如一个文件夹内全部 PDF），识别后全部入池 | 支持多选文件 / 拖拽文件夹；全部进入发票池 |
| US-02 | 财务/报销人 | 在发票箱页也使用同样的上传界面，一次上传多份 | 发票箱的「批量上传并识别」按钮弹出统一上传组件 |
| US-03 | 财务/报销人 | 在挂发票弹窗中能看到发票池中已识别、尚未挂接的发票 | 列表显示 `invoice_inbox` 中 status=recognized 的记录 |
| US-04 | 财务/报销人 | 在挂发票弹窗中选中池中发票 → 确认挂接 → 自动转为正式 Invoice + 绑定到当前 bill+item | 池中记录变 linked，正式 Invoice 出现 |

### P1（本次做，允许简版）

| ID | 角色 | 故事 | 验收标准 |
|----|------|------|---------|
| US-05 | 财务/报销人 | 上传后可批量编辑识别结果（改销方/金额等）再确认入池 | 上传后展示识别结果列表（一行一张），可展开编辑 |
| US-06 | 财务/报销人 | 发票箱列表可筛选「待识别 / 已识别 / 已挂接」 | 已有，保持 |
| US-07 | 财务/报销人 | 发票箱可挂接（转正式）到已有报销单或采购单 | 已有「挂接」按钮，保持 |

### P2（后续迭代）

## 4. UI 设计稿

### 4.1 统一上传组件（基于财务管理样式）

```
┌──────────────────────────────────────────┐
│ 上传发票自动识别                 × 关闭   │
├──────────────────────────────────────────┤
│                                          │
│  ┌──────────────────────────────────┐    │
│  │  点击上传或拖拽发票文件到此处      │    │
│  │     (支持 PDF / OFD / 图片)      │    │
│  │     也可拖拽整个文件夹            │    │
│  └──────────────────────────────────┘    │
│       已选 N 个文件：                    │
│    ┌── 20260701_专票_供应商A_100.pdf   │
│    ├── 20260701_普票_供应商B_50.pdf    │
│    ├── 20260702_火车票_深圳北_75.pdf   │
│    └── (点击×可移除单条)               │
│                                          │
│  ── OCR 识别结果 ──                      │
│  □ | 文件名 | 发票号码 | 销方 | 金额 |  │
│  □ | xxx   | 12345  | 公司A | 100  | 状态 │
│  □ | yy   | 67890  | 公司B | 50    | 正确 │
│    ↑ 点击行展开编辑字段                    │
│                                          │
│  [取消]           [全部暂存到发票池]       │
└──────────────────────────────────────────┘
```

### 4.2 挂发票弹窗更新

现有弹窗保持不变，**发票源**改为：
- `invoice_inbox` 中 `status='recognized'` 且 `linked_doc_id IS NULL` 的记录（池中已识别的）
- `invoices` 中 `reimbursement_bill_id IS NULL` 的记录（已转正式未挂接）
- 两源合并去重显示

## 5. 数据流

```
┌─────────────┐    ┌──────────────────┐    ┌─────────────┐
│ 上传发票入口 │───→│ invoice_inbox 表  │───→│ 挂发票弹窗   │
│ (统一组件)   │    │ (发票池 / 暂存)   │    │ (选择挂接)   │
│             │    │                  │    │             │
│ • 报销单页  │    │ status=pending   │    │ → 转正式     │
│ • 发票箱页  │    │ → recognized     │    │   Invoice    │
│ • 采购单页  │    │ → linked         │    │   + batchLink│
└─────────────┘    └──────────────────┘    └─────────────┘
```
