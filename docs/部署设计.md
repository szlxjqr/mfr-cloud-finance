## 1. 引言

### 1.1 适用范围与部署形态

**适用范围**：智慧经营（Cloud Finance）系统单实例全栈部署。

**部署形态**：私有化（单机）+ 可选容器化。单机即可支撑 30 人公司全场景，QPS ≤ 10。

### 1.2 名词与缩写

| 名词 | 含义 |
| --- | --- |
| SQLite | 嵌入式文件数据库 |
| FastAPI | Python 异步 Web 框架 |
| Vue 3 | 前端 SPA 框架 |
| Nginx | 反向代理 + 静态文件托管 |
| HOMEBREW | macOS 包管理器 |
| pyenv | Python 版本管理 |

## 2. 部署架构

### 2.1 部署视图

```
┌──────────────────── 公司内网 / 单机 ────────────────────┐
│                                                        │
│  [Browser Browser Browser]                             │
│         │ HTTPS (Nginx)                                │
│         │                                              │
│  ┌──────▼────────┐         ┌──────────────────────┐    │
│  │  Nginx (443)  │ ──────► │  FastAPI :8521       │    │
│  │  reverse proxy│         │  (uvicorn)           │    │
│  │  + SPA static │         │                      │    │
│  └───────────────┘         │  /api/* 业务 API     │    │
│         │                  │  /auth/* 鉴权        │    │
│         └─► static dist/   │                      │    │
│                            └──────────┬───────────┘    │
│                                       │                │
│                            ┌──────────▼───────────┐    │
│                            │  SQLite 文件           │    │
│                            │  backend/smart_finance│    │
│                            │  .db                   │    │
│                            └────────────────────────┘    │
│                                                        │
│  ┌─────────────────────────┐                           │
│  │  本地备份 tar 包         │  ← crontab 每日 03:00   │
│  │  ~/backups/yyyymmdd.tgz │                           │
│  └─────────────────────────┘                           │
└────────────────────────────────────────────────────────┘
```

### 2.2 网络分区

| 区域 | 用途 | 安全级别 |
| --- | --- | --- |
| 公网（老板家中宽带） | HTTPS 反向代理入口 | 中 |
| DMZ | Nginx 443 only | 中 |
| 内网 | FastAPI :8521 + SQLite | 高（仅 localhost） |
| 本地存储 | uploads/, .auth_secret, smart_finance.db | 最高（仅本机用户） |

### 2.3 部署形态选型对比

| 维度 | 单机 + Python | 单机 + Docker | K8s |
| --- | --- | --- | --- |
| 复杂度 | 低 | 中 | 高 |
| 资源占用 | 极低 | 中 | 高 |
| 备份 | cp + tar | docker volume + tar | PersistentVolume + Snapshot |
| **当前决策** | **✅ 推荐（MVP）** | 完整版评估 | 不适用 |

## 4. 部署流水线

### 4.1 准备

```bash
# 1) 克隆仓库
git clone https://github.com/szlxjqr/mfr-cloud-finance.git
cd mfr-cloud-finance

# 2) 后端虚拟环境
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# 启动一次自动 init_db() 建表 + 种子
uvicorn app.main:app --port 8521
# 立即 Ctrl+C，首次 .auth_secret 已生成

# 3) 前端构建
cd ../frontend
npm install
npm run build        # 产出 dist/

# 4) 上传文件目录
mkdir -p ../backend/uploads/invoices ../backend/uploads/inbox
```

### 4.2 CI 流程（当前手动，建议 GitHub Actions）

```yaml
name: build-and-test
on: [push]
jobs:
  backend-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: {python-version: '3.11'}
      - run: |
          cd backend
          pip install -r requirements.txt
          pip install pytest
          pytest -q
  frontend-build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: {node-version: '22'}
      - run: |
          cd frontend
          npm ci
          npm run build      # vue-tsc + vite build
          node tests/invoice_accuracy.mjs
```

### 4.3 发布流程（手动）

```bash
# 1) 拉取最新
cd /Users/szlxjqr/Developer/mfr-cloud-finance
git pull origin main

# 2) 后端依赖增量更新
cd backend && source .venv/bin/activate && pip install -r requirements.txt

# 3) 前端重新构建
cd ../frontend && npm run build

# 4) 重启 FastAPI（reload 模式无需重启，但保险手动重启）
cd ..
pkill -f "uvicorn app.main" || true
sleep 1
cd backend && nohup .venv/bin/python -m uvicorn app.main:app --port 8521 > backend.log 2>&1 &

# 5) Nginx 重载（修改配置后）
nginx -t && nginx -s reload
```

## 7. 数据备份与恢复

### 7.1 备份策略

| 时点 | 内容 | 频率 | 保留 |
| --- | --- | --- | --- |
| 每日 03:00 | SQLite + uploads/ + .auth_secret + docs/ | 每天 | 30 天 |
| 每周日 02:00 | 整库快照 | 每周 | 12 周 |
| 每月 01:00 | 全量归档（tar.gz） | 每月 | 永久 |

### 7.2 备份命令

```bash
BACKUP_DIR=~/backups
TODAY=$(date +%Y%m%d)
mkdir -p $BACKUP_DIR
cd /Users/szlxjqr/Developer/mfr-cloud-finance
tar czf $BACKUP_DIR/${TODAY}_full.tgz \
  --exclude='backend/.venv' \
  --exclude='frontend/node_modules' \
  --exclude='frontend/dist' \
  backend/smart_finance.db \
  backend/.auth_secret \
  backend/uploads/ \
  docs/
echo "backup ok: $BACKUP_DIR/${TODAY}_full.tgz"
# 保留 30 天
find $BACKUP_DIR -name "*_full.tgz" -mtime +30 -delete
```

### 7.3 crontab 接入

```bash
crontab -e
0 3 * * * /bin/zsh -c "$HOME/scripts/backup-mfr.sh"
```

### 7.4 恢复

```bash
cd /Users/szlxjqr/Developer/mfr-cloud-finance
tar xzf ~/backups/20260724_full.tgz
# 解压恢复：
#   backend/smart_finance.db ← 文件级覆盖
#   backend/.auth_secret ← 文件级覆盖（重要，保留原 secret 避免 token 失效）
#   backend/uploads/ ← 文件级覆盖
```

## 8. 应急回滚

### 8.1 回滚触发

- 业务单据生成凭证异常（5xx 频率 > 5%）
- 数据库锁表 / 磁盘满
- 关键功能不可用（如登录失败）

### 8.2 回滚步骤

```bash
# 1) 切到上一个稳定版本
cd /Users/szlxjqr/Developer/mfr-cloud-finance
git log --oneline -10
git checkout <GOOD_COMMIT>

# 2) 重启
pkill -f "uvicorn app.main" || true
sleep 1
cd backend && nohup .venv/bin/python -m uvicorn app.main:app --port 8521 > backend.log 2>&1 &

# 3) 数据恢复（如需）
cp ~/backups/YYYYMMDD_full.tgz /tmp/
tar xzf /tmp/YYYYMMDD_full.tgz -C .
```

### 8.3 数据库与代码不一致时的修复

- 后端 schema 变更都有 `_ensure_*_columns` 列迁移，新代码可在老 DB 启动
- 若失败：用上一个备份恢复

## 附录 A：Nginx 最小配置

```nginx
server {
    listen 443 ssl;
    server_name mfr.local;

    ssl_certificate /opt/homebrew/etc/nginx/ssl/mfr.crt;
    ssl_certificate_key /opt/homebrew/etc/nginx/ssl/mfr.key;

    # SPA 静态
    root /Users/szlxjqr/Developer/mfr-cloud-finance/frontend/dist;
    index index.html;

    # API 代理
    location /api/ {
        proxy_pass http://127.0.0.1:8521/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 60s;
    }

    # SPA fallback
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```
